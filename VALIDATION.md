# Проверка версии 2.0.0 — 14 октября 2026 года

## Выполнено

- `python3 -m unittest discover -s tests -v`: **103 выполненных тестов, все прошли**, без пропусков. Включены сохранённые регрессионные тесты; тесты старых пользовательских действий источников/избранного обновлены на проверку их отключения с сохранением старых данных.
- Реальные проверки кода: изоляция двух пользователей, перезапуск, сохранение ввода, комбинированные фильтры, неизвестные/будущие даты, все периоды свежести и границы DST, неизвестные языки, верхняя зарплата и периоды, истечение, страна, пагинация, правильные ссылки помощи и карточек, уведомления/отписка/удаление, повторные webhook в двух экземплярах, одновременные уведомления, миграция старой SQLite, независимая обработка медленного пользователя.
- Полный тестовый путь `JobPosting → parser → SQLite upsert → фильтры → карточка → уведомление → повтор после перезапуска` с проверкой ссылок и истории.
- Настоящий HTTP-сервер на локальном сокете: запуск `serve()`, старт сборщика, GET `/health` с `ok=true, version=2.0.0`; Telegram в этом тесте заменён имитацией, внешняя регистрация webhook не выполнялась.
- `python3 tools/validate_postgres.py` с pgserver 0.1.4 / PostgreSQL 16: SQL применён дважды, сохранение прежних настроек и истории, атомарные JSON-патчи, конкурентная аренда сборщика (победитель один), постоянный webhook claim, триггер неизменной даты первой публикации, доступ только service_role, удаление личных данных с сохранением общих вакансий. Все проверки прошли.
- Повторный живой проход: 379 полученных записей, пять новых ссылок; в SQLite 384 уникальных пары source/url, дубликатов нет.
- Компиляция всех рабочих модулей на Python 3.12.14 прошла.
- Живой сбор: первый проход **379** действующих записей из семи источников. Разбор и сохранение выполнены реальным кодом, без демонстрационных вакансий. Доступ/ограничения всех двенадцати источников проверены отдельно: `SOURCE_NOTES.md`.
- Официальные бесплатные тарифы Render, Supabase и GitHub Actions проверены; ссылки и ограничения приведены в `START_WITH_IPHONE.md`.

## Что этим не подтверждается

Рабочий Render в начале задачи обслуживал прежнюю версию (`/health` без номера). Подготовленная новая версия не становится работающей от одной проверки локального кода.

Для проверки обновлённого production нужны применение SQL к действующей Supabase, публикация кода в используемую Render ветку, deploy и фактическое взаимодействие двух пользователей в Telegram. Адрес существующей базы известен, серверный ключ в этой среде на момент проверки отсутствовал. Значения секретов не извлекались из Render и не запрашивались в переписку.

Бесплатный сервер засыпает; GitHub schedule допускает задержки/пропуски. Доставка ровно в выбранную минуту не обещается. Авария между успешной внешней отправкой Telegram и записью истории может привести к редкому повтору; штатные пересечения задач и повторные webhook защищены арендами и постоянной историей.

Источник `ok` подтверждает получение ограниченной выборки в конкретном проходе, а не постоянную доступность/полноту. У Halo текущая проверенная выборка истекла, Careerjet ограничивает доступ, Sale-me вернул 404, Lako требует неподтверждённого API, HelloWorld требует разрешения.
