# Работа в Сербии — Telegram-бот 2.6.0

Многопользовательский бот работает в **Telegram Serverless**: обработчики на JavaScript и встроенная SQLite. Сборщик на Python 3.11+ запускается через GitHub Actions и использует все 98 источников. [Устройство, миграция и обслуживание](serverless/README.md). Прежняя [инструкция Render/Supabase](START_WITH_IPHONE.md) сохранена для этой схемы развёртывания.

Отдельная [проба Telegram Serverless](serverless-probe/README.md) проверяет импорт до трёх вакансий, встроенную SQLite и уведомления владельцу через `tgcloud run`. Запускается вручную в GitHub Actions, не публикует обработчики и не переключает webhook. Это эксперимент, а не выполненная миграция рабочего бота.

Перенос выполнен: webhook основного @SerbiaJobsBot направлен на Telegram Serverless, пользователи и история уведомлений сверены и сохранены. Render приостановлен, старый workflow отключён. Workflow **Serbia Jobs Serverless** выполняет сбор; расписание GitHub может задерживаться. Supabase содержит резервную копию на момент переноса и больше не обновляется ботом.

## Источники

**Все 98 источников включены по умолчанию**: 15 сайтов/лент и 83 публичных адреса Telegram-канала. Пользователь не выбирает источники; старые сохранённые списки источников не ограничивают поиск и уведомления. Список каналов находится в `channel_catalog.py`: Сербия, международный найм и релокация, разработка, QA, управление, маркетинг, дизайн и HR. Полный охват всех существующих каналов не гарантируется; состояние каждого источника проверяется сборщиком.

Telegram читается через публичные страницы `t.me/s/…`, без аккаунта пользователя, приглашений в группы и доступа к закрытой переписке. Принимаются объявления о найме с явным указанием Сербии или сербского города; резюме, «ищу работу», услуги и закрытые вакансии исключаются по текстовым правилам. В международных каналах отбираются только предложения для Сербии. За проход читаются до двух страниц и 60 сообщений на канал. Между запросами ко всем каналам выдерживается общая пауза не меньше 1,5 секунды; соблюдается robots.txt. Изменение текста того же поста сохраняет его ID и историю уведомлений. Повторы объединяются в поиске и уведомлениях по исходной ссылке либо по строгому совпадению текста и реквизитов. Скрытие распространяется на все распознанные копии. Исходные записи и история сохраняются; неоднозначные совпадения остаются отдельными. [Правила объединения](serverless/README.md#повторные-вакансии-и-обновление-кода).

Добавлена официальная RSS-лента **Poslovi Infostud**. Она содержит последние записи, а не весь архив. Наличие источника в каталоге не подтверждает его текущую доступность: закрытый канал, запрет robots.txt и сетевой сбой отражаются в диагностике. Начальный список каналов взят из публичного [каталога вакансий](https://github.com/QaIliapro/Job-).


В каталог добавлены **Startit Poslovi** (IT) и **Omladinska zadruga Bulevar** (студенческие и молодёжные вакансии). Все источники проверяются общим сборщиком автоматически; менять пользовательские настройки не требуется. Объявления Bulevar сохраняют условия участия и исходную почасовую зарплату, которая не превращается в месячный минимум.

Исправлен Halo oglasi: актуальные данные берутся из публичного объекта страницы, используемого самим сайтом; устаревшая JSON-LD разметка больше не исключает продлённые вакансии. Lako do posla подключён через анонимный API, адрес которого опубликован в клиентском коде сайта. Сохраняются только поля вакансии, без объектов учётных записей работодателей и служебных данных. Запросы проверяют robots.txt отдельно на API-домене; внешние адреса вне явно разрешённых доменов не обходятся.

Подключение не означает полный обход истории сайта. Один проход ограничен двумя HTML-страницами списка и восемью подробными карточками на источник; Klik — четырьмя страницами ленты, SerbiaHub — двумя страницами по 50, Lako — первой страницей списка и восемью карточками. Не более трёх источников одновременно, пауза не меньше 1,5 секунды с учётом robots.txt. Точные результаты, отключённые источники и причины приведены в [SOURCE_NOTES.md](SOURCE_NOTES.md).

## Поведение

Главное меню: **🔎 Найти вакансии · ⚙️ Фильтры · 🔔 Уведомления · 🙈 Скрытые вакансии · 💬 Помощь**. Меню показывает выбранные условия, текущий режим уведомлений и число скрытых вакансий отдельными строками; короткая подсказка объясняет поиск и фильтры. `/start` и `/menu` открывают меню без блока «Перед началом» и предупреждения о тестовом режиме. «Помощь» объясняет, что владельцу можно написать по вопросам настроек, ошибок и неисправностей. Тега в тексте нет; кнопка «Написать владельцу» ведёт на https://t.me/AngryVirus. Источники и избранное убраны из интерфейса, команд и действий старых кнопок. Название источника и исходная ссылка остаются в карточках.

Фильтры: слова (ИЛИ), исключения, пять городов/вся Сербия, удалённо/на месте, русский/сербский/английский/не важно, нижняя месячная зарплата в EUR или RSD, вакансии без зарплаты, календарная свежесть сегодня/вчера/7/30 дней/не важно. **Города, языки, формат и свежесть поддерживают несколько вариантов**: внутри группы действует ИЛИ, между группами — И. Галочки показывают выбор; изменения сохраняются сразу, повторное нажатие снимает отметку. «Не важно»/«Вся Сербия»/«Любой формат» сбрасывают ограничения соответствующей группы. При снятии последнего варианта также включается «любой». Пересекающиеся периоды объединяются, например «7 дней» включает сегодня и вчера. Неизвестность не является доказательством языка, даты или удалённости. Гибрид не равен полностью удалённой работе. «До X» не означает гарантированный минимум X.

**«🪪 Наличие ВНЖ»** — отдельный фильтр требования работодателя: **«Да»** оставляет вакансии с явным требованием ВНЖ, **«Нет»** — с явным указанием, что ВНЖ не требуется, **«Не важно»** — все вакансии, включая объявления без такого условия. Выбирается один вариант; повторное нажатие сохраняет выбор. Неизвестное условие, помощь с оформлением и обязанности кадровика не означают «Нет». Противоречивые или условные формулировки остаются неизвестными. Распознаются распространённые явные формулировки на русском, сербском и английском; сложные или нераспознанные условия проверяйте в оригинале. Фильтр применяется и к уведомлениям, сохраняется отдельно для каждого пользователя и сбрасывается в «Не важно» общей кнопкой сброса. Работает с уже сохранёнными заголовками и описаниями, без миграции SQL и новых сетевых запросов. Результат разбора публичного текста кэшируется в памяти до 1024 записей; изменение текста даёт новый результат.

Свежесть считается в Europe/Belgrade с DST. Время первого сбора не заменяет дату публикации. Не выдаются будущие публикации, явно истёкшие вакансии и объявления с подтверждённым неподходящим расположением/ограничением страны. Неизвестные факты не придумываются. Контакты извлекаются только из исходного описания. Поиск и уведомления имеют кнопку перехода к исходному объявлению, выдача по одной карточке со счётчиком и кнопками «Предыдущая / Следующая». Поиск редактирует текущее сообщение, а не добавляет новые объявления в историю.

Меню и карточки оформлены средствами Telegram: жирные заголовки, курсив, блоки цитат, без предпросмотра ссылок. Карточка компактная: должность, компания/место, зарплата, языки, короткое описание, дата и источник. **«Подробнее» / «Свернуть»** меняют то же сообщение, оригинал всегда доступен по ссылке. **«Скрыть»** исключает вакансию из будущего поиска и уведомлений только для нажавшего пользователя. После скрытия в просмотрщике сразу открывается следующая подходящая вакансия. В **«🙈 Скрытые вакансии»** есть пагинация и восстановление отдельных объявлений. Скрытие сохраняется после обновления объявления и перезапуска. Восстановление учитывает текущие фильтры и сохраняет историю уведомлений; уже отправленная вакансия повторно не рассылается. Сброс фильтров не очищает скрытые вакансии.

**«🇷🇺 Перевести на русский»** переводит заголовок и описание карточки прямо в сообщении; **«Оригинал»** возвращает исходный текст. Перевод доступен также в уведомлениях. Зарплата, контакты, ссылка и исходная запись остаются прежними. Переводится текст, доступный в карточке (до 1800 UTF-16 единиц описания); полное объявление открывается по ссылке. Используется публичный сервис Google без API-ключа: доступность и квоты не гарантируются. Успешные фрагменты кэшируются в памяти (до 256), ошибки не кэшируются; при сбое есть повтор и перевод в браузере. В сервис отправляется только публичный текст объявления.

В отдельных экранах выбора фильтров оставлены варианты, **«Готово»** и возврат в меню; одна кнопка поиска находится на общем экране фильтров. При пустой выдаче бот показывает выбранные условия, число доступных вакансий без ограничений этих фильтров и до двух вариантов расширения поиска с реальными количествами. Самостоятельно условия не сбрасываются; скрытые, истёкшие и неподходящие по стране объявления не входят в подсказки. Если одного изменения недостаточно, бот сообщает об этом. Английский работает и для ранее сохранённых вакансий с явным требованием в описании, включая «знание английского»: фильтр и карточка используют одинаковые факты без изменения записей в базе. Языки учитываются только по явно указанным требованиям, а объявления без даты доступны при свежести **«Не важно»**.

Команды: `/start`, `/menu`, `/cancel`, `/delete_me`. У каждого пользователя сохраняются собственные фильтры, ввод и настройки уведомлений. Кнопка уведомлений в главном меню показывает «вкл/выкл» и переключает подписку одним нажатием. Новые подходящие вакансии отправляются по одной сразу после сохранения результатов отдельного источника, без ожидания остальных источников, ежедневного часа и прежнего ограничения в 10 вакансий. При включении или повторном включении старый каталог не рассылается. Прежние ежедневные подписки становятся подписками на новые вакансии; при первом запуске после обновления устанавливается начальная граница, чтобы не отправлять архив.

Адрес рабочего места, явно указанный в структурированных данных или тексте, выводится одной кликабельной ссылкой Google Maps в поиске и уведомлениях. Ссылка открывает поиск по исходному адресу, а не по выдуманным координатам. Если точного адреса нет, кликабельным остаётся город; явные ссылки Google Maps и координаты также сохраняются. Перевод карточки сохраняет исходный адрес.

Отправка происходит после обнаружения вакансии: по умолчанию сбор запускается каждые 30 минут после завершения предыдущего прохода, а сам проход большого каталога занимает дополнительное время. Это не мгновенная доставка в момент публикации в стороннем канале; спящий Render и недоступность источника также увеличивают задержку.

## Хранение и совместимость

Обновление 2.5 → 2.6 не требует SQL-миграции: адрес сохраняется в существующем поле `location` или извлекается из исходного описания, граница новых уведомлений — в JSON настроек. Исходные данные и история отправок сохраняются.

В production обязателен Supabase. **Обновление 2.0/2.1/2.2 → 2.3 не требует нового SQL**: множественный выбор и список ID скрытых вакансий хранятся в существующем JSON `sj_users.settings` через уже установленный атомарный RPC. Старые одиночные значения читаются с прежним смыслом, остальные настройки и история сохраняются. Для первого запуска или обновления с 1.x выполните **весь** `supabase-schema.sql` в SQL Editor существующего проекта. Скрипт идемпотентный и добавляет колонки/функции без очистки пользователей, вакансий, избранного старой версии и истории отправок. Старый внутренний фильтр `no_serbian` сохраняет смысл до нового выбора пользователя; в новом меню его нет. Старые списки источников хранятся для обратимой миграции, но поиск использует фиксированный каталог целиком.

Кнопки подтверждаются до обращения к базе. Настройки повторно используются только внутри одного обработчика; каждое новое нажатие получает актуальные данные. Upsert пользователя сохраняет прежние настройки, RPC возвращает результат записи для немедленного отображения галочек.

JSON-настройки обновляются атомарным RPC на уровне отдельных полей. Коллекция защищена общей арендой в базе, уведомления — отдельной арендой пользователя и общей с webhook арендой его настроек. Webhook update_id хранится в базе, повтор после перезапуска не переключает настройку второй раз. Разные пользователи обрабатываются независимо, сетевой/SQL ввод-вывод вынесен из основного event loop. Первоначальная дата публикации и ID записи сохраняются при upsert.

Идеальную exactly-once доставку через Telegram обещать нельзя: авария между успешной отправкой сообщения и записью истории может привести к редкому повтору. Пересекающиеся штатные проверки, повторы webhook и перезапуски без такой аварии защищены.

## Локальная разработка

Linux с tzdata, Python 3.11+, стандартные sqlite3/zoneinfo/urllib. На Windows без базы часовых поясов потребуется пакет tzdata. Секреты не нужны для тестов и однократного сбора в SQLite.

```bash
python3 -m unittest discover -s tests -v
python3 bot.py --collect
python3 bot.py --status
```

Для long polling задайте приватно `TELEGRAM_BOT_TOKEN` и запустите `python3 bot.py`. Не запускайте второй polling-процесс или polling поверх установленного webhook. SQLite автоматически расширяет старую схему без удаления данных. Если оба SUPABASE-параметра установлены, CLI использует удалённую базу; задайте их пустыми для локального SQLite.

При ошибке обработки polling повторяет необработанное обновление через пять секунд и только после успеха переходит к следующим. Постоянная ошибка останавливает продвижение очереди до устранения причины; она записывается в журнал как `Update failed (…)`. Это предотвращает преждевременное подтверждение пропущенных команд.

Для воспроизводимого замера поиска и переходов между карточками на синтетическом каталоге:

```bash
python3 tools/benchmark_search.py
```

По умолчанию проверяются 1 000, 10 000 и 50 000 вакансий: настоящий SQLite и модель постраничного чтения Supabase без HTTP. Результаты выводятся в JSON; `--sizes`, `--repeats` и `--page-delay-ms` позволяют менять объём, число повторов и моделируемую задержку страницы. Временная база удаляется после замера. Это не измерение задержки работающего Telegram-бота.

Для дополнительной проверки SQL в отдельном временном PostgreSQL (это только dev-зависимость):

```bash
python3 -m pip install pgserver==0.1.4
python3 tools/validate_postgres.py
```

## Production

```text
Build: python3 -m compileall -q bot.py sources.py store.py cloud_store.py web_server.py job_metadata.py filters.py
Start: python3 bot.py --webhook
Health check: /health
```

`.env.example` перечисляет приватные поля без реальных значений. На Render данные не записываются в SQLite: `--webhook` требует Supabase. `/health` содержит версию и отвечает 503 до проверки схемы и Telegram. Сбор запускается при старте, затем внутренним таймером; `.github/workflows/collect.yml` дополнительно пробуждает спящий сервер каждые 30 минут. `/telegram` и `/collect` имеют разные секреты.

Диагностика владельца: `sj_source_status` в Supabase и Render Logs. Пользователю показываются разные состояния: идёт наполнение, нет совпадений, временная недоступность сайтов. Ошибки одного источника не останавливают другие.

## Проверка и границы

[Отчёт](VALIDATION.md), [источники и способы получения](SOURCE_NOTES.md). Тесты с подменами API проверяют приложение; отдельный живой сбор проверяет доступность сайтов. Готовность рабочего Render и его действующей Supabase подтверждается только после применения миграции, deploy и взаимодействия в Telegram. Содержимое старого `/health` без версии не подтверждает обновление.

Сохраняются Telegram user/chat ID, настройки и история уведомлений; публичные вакансии общие. `/delete_me` удаляет личные записи и прежнее избранное, оставляя общую базу вакансий. Имена, username и произвольная переписка пользователей не хранятся. Перед публичным запуском разместите политику обработки этих данных. Бесплатная инфраструктура имеет лимиты, паузы и задержки — подробности и официальные ссылки в инструкции для iPhone.
