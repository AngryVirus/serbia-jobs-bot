# Работа в Сербии — Telegram-бот 2.0.0

Многопользовательский бот на Python 3.11+ (проверен 3.12.14), без платных API и без сторонних библиотек во время работы. Бесплатная схема: Render Web Service + Supabase + GitHub Actions. [Запуск и обновление с iPhone](START_WITH_IPHONE.md).

## Поведение

Главное меню: **🔎 Найти вакансии · ⚙️ Фильтры · 🔔 Уведомления · 🆘 Помощь**. Помощь ведёт на https://t.me/AngryVirus. Источники и избранное убраны из интерфейса, команд и действий старых кнопок. Название источника и исходная ссылка остаются в карточках.

Фильтры: слова (ИЛИ), исключения, пять городов/вся Сербия, удалённо/на месте, русский/сербский/не важно, нижняя месячная зарплата в EUR или RSD, вакансии без зарплаты, календарная свежесть сегодня/вчера/7/30 дней/не важно. Категории применяются вместе (И). Неизвестность не является доказательством языка, даты или удалённости. Гибрид не равен полностью удалённой работе. «До X» не означает гарантированный минимум X.

Свежесть считается в Europe/Belgrade с DST. Время первого сбора не заменяет дату публикации. Не выдаются будущие публикации, явно истёкшие вакансии и объявления с подтверждённым неподходящим расположением/ограничением страны. Неизвестные факты не придумываются. Контакты извлекаются только из исходного описания. Поиск и уведомления имеют ссылку и кнопку на конкретную вакансию, выдача по пять.

Команды: `/start`, `/menu`, `/cancel`, `/delete_me`. У каждого пользователя сохраняются собственные фильтры, ввод и настройки уведомлений. Подборки: выключены / после проверки / раз в день по часу Белграда, не более 10 вакансий за проход.

## Хранение и совместимость

В production обязателен Supabase. Перед новой версией выполните **весь** `supabase-schema.sql` в SQL Editor существующего проекта. Скрипт идемпотентный и добавляет колонки/функции без очистки пользователей, вакансий, избранного старой версии и истории отправок. Старый внутренний фильтр `no_serbian` сохраняет смысл до нового выбора пользователя; в новом меню его нет. Старые списки источников хранятся для обратимой миграции, но поиск использует фиксированный каталог целиком.

JSON-настройки обновляются атомарным RPC на уровне отдельных полей. Коллекция защищена общей арендой в базе, уведомления — отдельной арендой пользователя. Webhook update_id хранится в базе, повтор после перезапуска не переключает настройку второй раз. Разные пользователи обрабатываются независимо, сетевой/SQL ввод-вывод вынесен из основного event loop. Первоначальная дата публикации и ID записи сохраняются при upsert.

Идеальную exactly-once доставку через Telegram обещать нельзя: авария между успешной отправкой сообщения и записью истории может привести к редкому повтору. Пересекающиеся штатные проверки, повторы webhook и перезапуски без такой аварии защищены.

## Локальная разработка

Linux с tzdata, Python 3.11+, стандартные sqlite3/zoneinfo/urllib. На Windows без базы часовых поясов потребуется пакет tzdata. Секреты не нужны для тестов и однократного сбора в SQLite.

```bash
python3 -m unittest discover -s tests -v
python3 bot.py --collect
python3 bot.py --status
```

Для long polling задайте приватно `TELEGRAM_BOT_TOKEN` и запустите `python3 bot.py`. Не запускайте второй polling-процесс или polling поверх установленного webhook. SQLite автоматически расширяет старую схему без удаления данных. Если оба SUPABASE-параметра установлены, CLI использует удалённую базу; задайте их пустыми для локального SQLite.

Для дополнительной проверки SQL в отдельном временном PostgreSQL (это только dev-зависимость):

```bash
python3 -m pip install pgserver==0.1.4
python3 tools/validate_postgres.py
```

## Production

```text
Build: python3 -m compileall -q bot.py sources.py store.py cloud_store.py web_server.py job_metadata.py filters.py
Start: python3 bot.py --webhook
Health check: /health
```

`.env.example` перечисляет приватные поля без реальных значений. На Render данные не записываются в SQLite: `--webhook` требует Supabase. `/health` содержит версию и отвечает 503 до проверки схемы и Telegram. Сбор запускается при старте, затем внутренним таймером; `.github/workflows/collect.yml` дополнительно пробуждает спящий сервер каждые 30 минут. `/telegram` и `/collect` имеют разные секреты.

Диагностика владельца: `sj_source_status` в Supabase и Render Logs. Пользователю показываются разные состояния: идёт наполнение, нет совпадений, временная недоступность сайтов. Ошибки одного источника не останавливают другие.

## Проверка и границы

[Отчёт](VALIDATION.md), [источники и способы получения](SOURCE_NOTES.md). Тесты с подменами API проверяют приложение; отдельный живой сбор проверяет доступность сайтов. Готовность рабочего Render и его действующей Supabase подтверждается только после применения миграции, deploy и взаимодействия в Telegram. Содержимое старого `/health` без версии не подтверждает обновление.

Сохраняются Telegram user/chat ID, настройки и история уведомлений; публичные вакансии общие. `/delete_me` удаляет личные записи и прежнее избранное, оставляя общую базу вакансий. Имена, username и произвольная переписка пользователей не хранятся. Перед публичным запуском разместите политику обработки этих данных. Бесплатная инфраструктура имеет лимиты, паузы и задержки — подробности и официальные ссылки в инструкции для iPhone.
